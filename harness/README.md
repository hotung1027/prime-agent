# Harness

The continual harness is prime-agent's persistent layer: prompt notes, memories, skills and factory
machines that survive compaction and reload into every session.

**What is shareable and what is personal.** `skills/` and `machines/` are capabilities: they are
committed, reviewed and versioned here. `prompts/` and `memories/` are *your* agent's state - the
policy notes and durable facts a specific installation accumulated - so they are **git-ignored**.
Export them from a working agent dir when you want a backup; never commit them.

| dir | committed | loads from | contents |
|---|---|---|---|
| `skills/` | yes | the agent dir's skills | `SKILL.md` + optional Python |
| `machines/` | yes | `rlm.factory` machine library | `MACHINE.md` specs |
| `prompts/` | **no** (git-ignored) | injected into the system prompt | behavioural policy |
| `memories/` | **no** (git-ignored) | retrieved on demand | durable technical facts |

Install into an agent dir:

    cp -r skills/*   ~/.prime/agent/skills/
    cp -r machines/* ~/.prime/agent/machines/
    cp -r ../plugins/factory/machines/* ~/.prime/agent/machines/   # staged-delivery

The staged-delivery machine is generated by the factory plugin from `roles.py`; `feature-pipeline`
lives here.

## How this fits the runtime

`prime-agent-runtime/src/rlm/` is the code that loads these: `harness.py` owns the entries
(`prompt`/`memory`/`skill`/`subagent`/`factory`), `factory.py` runs the machines, `skill.py` discovers
skills. Nothing here patches the runtime - it is data the runtime reads.
